# Karipom Ear v2 — Step 1 確認手順書

- **文書番号**：KPE-STEP1-001 ／ **版数 v1.1**（実機ログ再監査反映：同期プローブ・フォーマット自動判定・mis指標を追加）／ 作成日 2026-07-12
- **対象**：Karipom_Ear_Pico_Step1_I2S_Verify.ino（Pico 2 + PCM1808単体検証）
- **準拠**：実装仕様書v2.0（KPE-IMPL-001）、設計書v1.3（KPE-ARCH-001）
- **スコープ**：Step 1のみ。UART送信・CoreS3接続・FFT・口パクは含まない

## 1. 事前条件（着手前チェック）

- ☐ 基板ジャンパ：OP1/OP2/OP3すべてOPEN（出荷状態＝M-96K・I2S-24）を目視＋導通確認
- ☐ 配線：**DATA→GP2／BCLK→GP3／LRCK→GP4**（3連番・順序厳守）、MCLK未接続、VDD→5V（VBUS 物理40番から仮給電）、GND共通
- ☐ 信号線3本＋（あれば）UART2本に220Ω直列抵抗
- ☐ Arduino IDE：ボード「Raspberry Pi Pico 2」（arduino-picoコア5.6.1）選択
- ☐ 通電中の配線変更をしない

## 2. 手順

1. 配線完了後、PicoをUSB接続（初回はBOOTSEL押下→UF2、以降はIDE直接書き込み）
2. スケッチを書き込み、シリアルモニタを115200bpsで開く
3. 起動バナーと `[ OK ] I2S begin 成功` → `[ OK ] ALIGN: attempt=N fmt=…` を確認（**v1.1**：起動時に同期プローブが走り、5.6.1スレーブ入力の位相ずれを自動修正。attemptは25回以内なら正常。**fmt=A/Bの判定結果を記録**——Step 2で固定値として使う）
4. **無音テスト**：3.5mmケーブルを音源に接続し、再生停止のまま30秒観察
5. **音楽テスト**：音源の音量50%以上で音楽を再生し30秒観察
6. **音量連動テスト**：音量を約2倍に上げ、rmsが明確に増えることを確認
7. **正弦波テスト（推奨）**：1kHzテストトーン（YouTube等）を再生し、min≈−max の対称性を確認
8. 各テストのシリアル出力をログ保存（右クリック→コピー等）し、ノイズフロア値をREADMEに記録

## 3. 想定シリアル出力例

起動時（1回だけ）：

```
============================================================
Karipom Ear v2 - Step 1 I2S Verify  (build Jul 12 2026 10:00:00)
MODE   : I2S INPUT + setSlave()  (PicoはBCLK/LRCK/MCLKを出力しない)
PINS   : DATA=GP2(DIN)  BCLK=GP3(DIN+1)  LRCK=GP4(DIN+2)  MCLK=未接続
FORMAT : bitsPerSample=32(固定) / fs=96000 Hz (M-96K想定。M-48K移行時はFS_HZ=48000に変更)
BUFFER : 8 x 256 words
EXPECT : BCLK 6.144MHz / LRCK 96.000kHz（基板出力・ロジアナ照合用）
24bit  : s24 = (raw<<1)>>8   [raw: bit30..7が音声データ, bit6..0=0]
============================================================
[ OK ] I2S begin 成功。同期プローブ開始...
[ OK ] ALIGN: attempt=2 fmt=A(data<<8, s24=raw>>8) 判定=確定
```

無音時（ケーブル接続・再生停止）の1秒毎統計行の例：

```
L[min=-406 max=398 dc=-2 rms=71 peak=405] | R[min=-395 max=411 dc=1 rms=69 peak=412] | n=95988 ovf=0 nd=0 mis=0 rawL=0xFFFFF300
```

音楽再生時の例：

```
L[min=-4182930 max=4507122 dc=-15 rms=812440 peak=4507137] | R[min=-3922011 max=4103055 dc=8 rms=776903 peak=4103047] | n=96011 ovf=0 nd=0 mis=0 rawL=0x3A5F1700
```

クロック未到達時（配線・ジャンパ不良）：

```
[NG ] この1秒間 受信0サンプル（累計3回）→ BCLK/LRCKが来ていない：配線順(GP2=DATA/GP3=BCLK/GP4=LRCK)・
      基板VDD=5V・ジャンパ全OPEN・GND共通 を確認
[TIMEOUT] 2秒以上サンプルなし。クロック未到達の可能性。
```

※数値は環境で変わる。見るのは**絶対値ではなく傾向**（下記判定基準）。

## 4. 判定基準

### 4.1 無音時に期待する傾向

- `n` ≈ 96,000（±10%以内。fsと一致＝フレーム同期が正しい最重要指標）
- `dc` ≈ 0（PCM1808は内蔵HPFでDC除去。|dc|が数千以上なら異常）
- `rms` は小さく安定（目安：数十〜数千。ケーブル・環境ノイズで変動）
- `min`/`max` はほぼ対称の小さい値
- `ovf`=0、`nd`=0、rawLの下位7bit（HEX末尾）はほぼ0系（…00/…80など）

### 4.2 音楽入力時に期待する傾向

- `rms` が無音時の**2〜3桁以上**に増加し、曲の強弱に追従して毎秒変化する
- `peak` が最大±8,388,607（24bitフルスケール）へ近づき得るが、通常再生では張り付かない
- `dc` は引き続き≈0のまま（音を入れてもdcが動かないのが正常）
- 音量2倍→`rms`が明確に増加（連動性＝正しい音声データの決定的証拠）

### 4.3 左右どちらかが0固定の場合

- **そのチャネルのデータが物理的に来ていない**：3.5mmケーブルの半挿し、モノラルプラグ使用、音源のバランス設定、基板CN3（R_IN/L_INヘッダ）との競合を確認
- L/R両方の`n`は正常なのに片方だけmin=max=0 → 配線ではなく**入力信号側**の問題（I2S受信自体は成立している）

### 4.4 値が飽和・二値化する場合（実例あり：v1.0で観測）

- **ワード境界ずれ（同期位相ずれ）が最有力**。実例：v1.0実機で `min=0 / max=131071 / dc≈65536 / rms≈65480`。無音時のADC出力が0と−1（全ビット1）でディザし、境界ずれにより全0／全1ワードが二値 {0, 131071} に化けたもの。**二値50:50混合の理論値（平均65536・標準偏差65535）と観測が一致**することで確定
- v1.1は起動時プローブ＋再同期でこれを自動回避する。`mis=0` が維持されていれば境界は正しい
- その他の原因：①`setBitsPerSample(32)`でない（24は禁止）②配線順違い（BCLK/LRCK取違え）

### 4.5 正常受信と誤フレーム解釈の区別（3点セット）

1. **無音≈0**：無音時rmsが小さい（誤解釈ならゴミが乗って大きくなる）
2. **音量連動**：音量とrmsが単調に連動する（誤解釈なら連動しない/不規則）
3. **1kHz正弦波で min≈−max・dc≈0**：さらに rms≈peak÷1.414（正弦波の理論比√2）に近ければ、振幅軸の解釈まで正しいと確定できる

### 4.6 Step 1合格条件（すべて満たすこと）

- ☐ `[ OK ] I2S begin 成功` と `[ OK ] ALIGN: attempt≦25 fmt=A/B 判定=確定` が表示される（**fmt判定を記録**）
- ☐ 全テストを通じて `mis=0` が維持される
- ☐ 無音30秒：`n`≈96,000・`dc`≈0・rms小・`ovf`=0・`nd`=0
- ☐ 音楽30秒：rmsが2桁以上増加し、曲の強弱に追従
- ☐ 音量2倍でrms明確増
- ☐ 1kHz正弦波：min≈−max、rms≈peak/1.414（±20%程度）
- ☐ L/R両チャネルとも有効値（片ch 0固定でない）
- ☐ 10分連続で `ovf`累計≦数回・`nd`=0・リセットなし
- ☐ （任意・推奨）M-48K移行試験：OP2をSHORT→FS_HZ=48000に変更→n≈48,000で同様に合格

合格後にStep 2（UART送信）へ進む。**1項目でも不合格のまま進まない。**

## 5. 設定と一次情報の対応表

| コードの設定 | 根拠（一次情報） |
|---|---|
| `I2S(INPUT)` + `setSlave()`（begin前） | arduino-pico 5.6.1 `I2S.cpp`：`_SLAVE+_INPUT` セレクタで `pio_i2s_in_slave_program` を選択。`setSlave()`は`_running`中は拒否＝begin前必須 |
| `setDATA(2)` のみでピン確定（GP3/GP4自動） | 5.6.1 `pio_i2s.pio.h` `pio_i2s_in_slave_program_init()` 内コメント「It's DIN, BCLK, LRCLK consecutive due to PIO limitations」＋ `pio_gpio_init(data_in_pin/+1/+2)` |
| `setBCLK()`を呼ばない | 同上（スレーブ入力ではCLOCK_BASEピンは無視、と実装コメントに明記）。誤解防止のため呼び出し自体を排除 |
| PicoがBCLK/LRCKを出力しない保証 | 同init内 `pio_sm_set_consecutive_pindirs(pio, sm, data_in_pin, 3, false)`＝3ピンとも入力方向 |
| `setBitsPerSample(32)`（24禁止） | PCM1808データシート：マスタモードBCK=64fs固定（32クロック/半フレーム）× 5.6.1のautopush閾値（32bit時32）＝1ワード1チャネルで整合。24指定は境界ずれ |
| `begin(96000)` | 基板裏面シルク（実機写真）：全OPEN=M-96K ＋ 搭載発振器24.576MHz（=256fs×96k、PCM1808 DSのマスタモード表と一致） |
| MCLK未接続 | PCM1808 DS：SCKIは基板発振器が常時供給。スレーブ時LRCK-SCKI同期要件（±6BCK超でADC停止・BPZゼロ出力）により外部クロック注入は不成立（旧戦略B廃止の根拠） |
| 24bit抽出（fmt自動判定：A=`raw>>8` ／ B=`(raw<<1)>>8`） | PCM1808 DS：I2S＝LRCKエッジ1BCLK後にMSB＋24bit後ゼロパディング。5.6.1のPIOプリアンブルがL半フレーム最初のBCLK立上りを消費するため取込開始はMSB位置（モデルA）が設計解釈。実機決着のため両モデルを起動時プローブで判別し、非データビットが常に0の方を採用 |
| 起動時同期プローブ＋end()/begin()再試行 | 5.6.1 `pio_i2s.pio.h` プリアンブル（wait 0 pin,1／wait 1 pin,1／jmp pin,0）は「LRCK=Low中の最初のBCLK立上り」で取込開始＝L半フレーム途中でSM有効化されると32bit境界が恒久的にずれる（autopushはビット計数のみ）。`end()`は設定を保持するため`begin()`のみで位相を引き直せる（5.6.1 I2S.cpp） |
| L=先・R=後 | 5.6.1スレーブ入力PIO：LRCK=Low区間の先頭に同期してから取込開始（I2S規約：LRCK Low=左ch） |
| `setBuffers(8,256)`（偶数ワード） | 溢れ時はバッファ単位破棄のため、偶数ワードでL/R偶奇が保存される（5.6.1 AudioBufferManager経由） |

参照：arduino-pico 5.6.1 タグの `libraries/I2S/src/I2S.cpp`・`pio_i2s.pio.h`（GitHub）、TI PCM1808データシート（SLES177）、実機基板裏面シルク写真（2026-07-12受領）。
